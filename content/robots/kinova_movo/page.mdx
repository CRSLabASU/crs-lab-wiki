## Software & Setup

### System architecture

MOVO runs on two onboard PCs (movo1 and movo2) connected via ROS. The system uses:

- **ROS Indigo** for robot control
- **MoveIt!** for motion planning
- **Kortex API** for arm control (similar to Gen3)
- **Gazebo** for simulation

### Networking

<Callout type="info">
  MOVO provides Wi-Fi network **MoVoWifi** and assigns IPs via DHCP. Default
  IPs: - movo2 PC: `10.66.171.1` - movo1 PC: `10.66.171.2` - Vector:
  `10.66.171.5` - Front laser: `10.66.171.8` - Rear laser: `10.66.171.9` - Right
  arm base: `10.66.171.15` - Left arm base: `10.66.171.16`
</Callout>

**Setup `/etc/hosts`:**

```
10.66.171.2 movo1
10.66.171.1 movo2
```

### Boot & power

1. Ensure E-stop is accessible and released
2. Power on main breaker
3. Wait for boot sequence (LEDs cycle)
4. Verify connection via SSH or ping

### Software environment

# ROS workspace
cd ~/movo_ws

## Validation & Diagnostics

### Boot diagnostics

```bash
# SSH into movo2
ssh movo@movo2

# Stop/start MOVO services
movostop
# Wait 10 seconds
movostart

# Check status
movochk
```

### Communication check

- Ping movo1: `ping 10.66.171.2`
- Ping movo2: `ping 10.66.171.1`
- List ROS topics: `rostopic list`

## Troubleshooting

| Issue                        | Possible Cause           | Solution                                |
| ---------------------------- | ------------------------ | --------------------------------------- |
| Can't connect to MOVO        | Not on same network      | Connect via Ethernet or MoVoWifi        |
| No response from movo1/movo2 | Wrong IP / network issue | Check /etc/hosts configuration          |
| Arms not responding          | ROS services not started | Run `movostart` and `roscore` on movo 2 |

## Safety & Maintenance

<Callout type="danger">
  MOVO is a heavy mobile platform. Keep clear of the path during navigation.
  Arms have pinch points. E-stop must be within reach at all times. Never work
  on the robot while powered on unless necessary.
</Callout>
