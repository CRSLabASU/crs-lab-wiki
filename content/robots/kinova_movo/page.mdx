The Kinova MOVO is a mobile manipulation platform with two **6-DOF Kinova JACO2 arms** (KG3 grippers), an omnidirectional mobile base, a pan-tilt head with a Kinect v2, two SICK lidars and a linear-actuator torso. It was selected for assessment and repair as part of the capstone project.

**Current state:** the robot brings itself up automatically at power-on (stands up, homes the arms, enables the base). The base, head and left arm are drivable with the joystick. The right arm executes MoveIt trajectories and moves from Kinova's Development Center, but ignores joystick (Cartesian) commands. A Kinova support ticket is open (see [Right arm issue](#right-arm-issue)).

### Connecting to MOVO

#### 1. Plug in

Connect an ethernet cable from your laptop to a free port on the robot's internal switch, or join **MoVoWifi**.

#### 2. Give your laptop an address on the robot's network

A direct ethernet connection usually has no DHCP, so set a static IP of **`10.66.171.100`**, mask **`255.255.255.0`**, and no gateway. Pick a different `.1xx` address if someone else is already connected.

**Linux:**

```bash
ip link                                       # find your ethernet interface, e.g. enp3s0
sudo ip addr add 10.66.171.100/24 dev enp3s0
```

**macOS** (adds the address alongside any existing one; resets on unplug or reboot):

```bash
networksetup -listallhardwareports            # find your ethernet device, e.g. en7
sudo ifconfig en7 alias 10.66.171.100 255.255.255.0
```

**Windows:** go to Settings → Network → Ethernet → IP assignment → Manual → IPv4, then enter IP `10.66.171.100` and subnet `255.255.255.0`.

#### 3. Add hostnames (optional, one time)

Add these lines to `/etc/hosts` (or `C:\Windows\System32\drivers\etc\hosts`):

```
10.66.171.2 movo1
10.66.171.1 movo2
```

#### 4. Verify and SSH in

```bash
ping -c 2 10.66.171.1
ssh movo@10.66.171.1        # movo2. Password: Welcome00
```

To find everything on the network: `sudo nmap -sn 10.66.171.0/24`. You should see both PCs, the base, both lidars and both arms.

<Callout type="tip">
  Nearly all work happens on **movo2**. Reach movo1 from inside movo2 with `ssh
  movo1`. That hop needs no password.
</Callout>

### Boot & power

MOVO brings itself up automatically. The upstart job `movo2-core` on movo2 handles this.

1. Make sure the E-stop is reachable and released, the arms are not resting on anything, and the area around the robot is clear.
2. Press the power button.
3. Wait about **2.5 minutes**. The robot will:
   1. Sync movo2's clock from movo1 (the dead CMOS battery workaround)
   2. Start the ROS master, both arm controllers and the joystick node on movo2
   3. Let movo1's `movo-core` bring up the base, lidars, Kinect, teleop and MoveIt
   4. **Stand up and home the arms**
   5. Put the base in tractor mode
4. Plug the joystick into **movo2**. It is ready to use.

Check progress from an SSH session on movo2:

```bash
tail -20 /tmp/movo_boot.log        # ends with "READY ... operational_state=5" when done
```

To shut down, **tap** the power button once. Do not hold it. Both PCs power off with the robot.

<Callout type="warning">
  The robot moves on its own about 2 minutes after power-on. Keep people and
  objects clear of the arms.
</Callout>

### Joystick (Logitech Extreme 3D Pro)

Plug it into **movo2**. Button numbers match the numbers printed on the stick.

| Button      | Function                                             |
| ----------- | ---------------------------------------------------- |
| 1 (trigger) | **Dead-man.** Hold it to move anything.              |
| 2 (thumb)   | Manual override                                      |
| 3           | Base standby                                         |
| 4           | Base tractor (enables driving)                       |
| 5 / 6       | Wrist motion (arm mode)                              |
| 7           | **E-stop**                                           |
| 8           | Home arms (close the fingers first; needs clearance) |
| 9           | Head (pan-tilt) mode                                 |
| 10          | Base mode                                            |
| 11          | Right arm mode (not working yet, see below)          |
| 12          | Left arm mode                                        |

In base mode, push the stick forward or back to drive, twist it to rotate, and push it sideways to strafe (the base is omnidirectional). If motion is very slow, push the throttle slider toward **+**.

### Kinova Development Center

Development Center is installed on movo2 at `/opt/JACO-SDK/GUI` and opens on the robot's HDMI monitor. It **only connects over USB.** Its ethernet mode is hard-coded to Kinova's factory IP (`192.168.100.10`), and the MOVO arms were re-addressed.

1. Connect a USB Type-B cable from the arm's base to movo2.
2. Stop the ROS arm controllers and launch Development Center:

```bash
sudo stop movo2-core
cd /opt/JACO-SDK/GUI && sudo env DISPLAY=:0 XAUTHORITY=$HOME/.Xauthority ./DevelopmentCenter.sh
```

3. Check **USB Enable** and uncheck Ethernet. The top-right corner shows which arm is connected.
4. When you're done, close Development Center, **unplug the USB cable**, and run `sudo start movo2-core`.

<Callout type="danger">
  Do not change the arm's **Ethernet / IP settings** in Development Center. The
  right arm must stay at `10.66.171.15` and the left arm at `10.66.171.16`, or
  MOVO cannot reach them.
</Callout>

<Callout type="info">
  The Gen2 SDK 1.5.1 Linux build shipped broken and needed two manual fixes: (1)
  the flattened symlinks in `/opt/JACO-SDK/GUI/lib` were restored, and (2) the
  missing Qt platform plugin `libqxcb.so` (Qt 5.7.1) was taken from the
  `PyQt5==5.7.1` wheel and placed in `/opt/JACO-SDK/GUI/platforms/`. The SDK's
  `installSDK64.sh` was **not** run, because it replaces the Kinova API 6.0.1
  that MOVO depends on.
</Callout>

```bash
date; ssh movo1 date                                         # clocks must match
rosnode list | grep -E "arm_ctl|movo_driver|move_group|joy"  # all should be present
rosnode info /move_group | grep -c arm_controller            # must be > 0

```

### Boot job control

```bash
sudo status movo2-core
sudo stop movo2-core
sudo start movo2-core
sudo tail -30 /var/log/upstart/movo2-core.log
ssh -t movo1 "sudo service movo-core status"    # movo1's stack
```

### Useful commands

| Task                   | Command                                                                                                                    |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Base to tractor        | `rostopic pub -1 /movo/gp_command movo_msgs/ConfigCmd '{gp_cmd: "GENERAL_PURPOSE_CMD_SET_OPERATIONAL_MODE", gp_param: 5}'` |
| Base to standby        | same as above with `gp_param: 4`                                                                                           |
| Home arms              | `rostopic pub -1 /movo/home_arms std_msgs/Bool 'data: true'`                                                               |
| Stand up + home again  | `rosnode kill /move_group; roslaunch movo_bringup movo_moveit.launch local:=true`                                          |
| Tuck (sit down)        | `roslaunch movo_demos tuck_robot.launch`                                                                                   |
| Drive without joystick | `rostopic pub -r 10 /movo/manual_override/cmd_vel geometry_msgs/Twist '{linear: {x: 0.1}}'`                                |

<Callout type="warning">
  `/movo/cmd_vel` is the **output** of the velocity mux. Publish to a mux input
  such as `/movo/manual_override/cmd_vel` instead.
</Callout>

### Right arm issue

The right arm executes MoveIt joint trajectories (startup and homing) and moves in both angular and Cartesian mode from Development Center over USB. It **ignores Cartesian velocity commands** from MOVO's driver (`/movo/right_arm/cartesian_vel_cmd`), so it does not respond to the joystick. The left arm works with the identical driver and settings.

The only configuration difference between the two arms is the **arm type**: the left is "JACO v2 6DOF Assist" and the right is "JACO v2 6DOF Service". The right arm's serial was also overwritten with `RIGHT ARM`. A factory restore did not change either. A support ticket with screenshots has been sent to Kinova (support@kinova.ca) asking how to set the right arm back to Assist.

## Troubleshooting

| Issue                                                  | Cause                                     | Solution                                                                                                            |
| ------------------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Can't ping or SSH the robot                            | Laptop not on `10.66.171.x`               | Set the static IP from [Connecting to MOVO](#connecting-to-movo); check the link light                              |
| movo2 shows the year 2013                              | Dead CMOS battery                         | The boot job fixes it. Manually: `sudo service chrony stop; sudo ntpdate -b 10.66.171.2; sudo service chrony start` |
| `Unable to communicate with master`                    | No ROS master                             | `sudo start movo2-core` (or `bash ~/MOVO-SCRIPTS/movo_teleop.sh`)                                                   |
| `invalid ROS_IP (an empty string)`                     | Sourcing a workspace cleared it           | `export ROS_IP=10.66.171.1` after `source`                                                                          |
| `run_id on parameter server does not match`            | movo1 connected before `roscore` finished | Start the master with `rosmaster --core` (the boot script does this)                                                |
| `shutdown request: new node registered with same name` | Two launches running the same nodes       | Don't run `movo_system_local.launch` on movo2; movo1's `movo-core` already starts those nodes                       |
| `_home_arm_planner failed (-4)` loop; arms frozen      | MoveIt started before the arm controllers | `rosnode kill /move_group; roslaunch movo_bringup movo_moveit.launch local:=true`                                   |
| Base won't drive                                       | Base in standby (`operational_state: 4`)  | Joystick button 4, or the tractor command above                                                                     |
| Joystick moves the head instead of the base            | Teleop in head mode                       | Press 10 for base mode                                                                                              |
| No `/dev/input/js0`                                    | Joystick on the wrong PC                  | Plug it into movo2                                                                                                  |
| `Kinova API failed: ... (1015)`                        | Arm request timed out                     | A single one at startup is harmless. If it repeats, check that Development Center is closed and USB unplugged       |
| Development Center: `Bind failed`                      | Another program holds the ports           | `sudo stop movo2-core; sudo pkill -f DevelopmentCenter`                                                             |
| Development Center won't connect                       | Using ethernet mode                       | Use USB; ethernet mode only targets `192.168.100.10`                                                                |

## Safety & Maintenance

<Callout type="danger">
  MOVO is a heavy mobile platform. Keep clear of the path during navigation.
  Arms have pinch points. E-stop must be within reach at all times. Never work
  on the robot while powered on unless necessary. The robot stands up and homes
  its arms automatically about 2 minutes after power-on.
</Callout>

### Best practices

- Keep the workspace clear for navigation
- Arms must not rest on anything at power-on (the fingers open during startup)
- Close the fingers before homing (button 8)
- Never force a JACO arm by hand while it's powered; the joints are not backdrivable
- Put the base back in standby (button 3) when you're done
- Back up `/home/movo/movo_ws_2` (movo2) and `/home/movo/movo_ws` (movo1) before code updates
- Log all sessions in the change log

### Demo scripts

| Demo                    | Command                                     |
| ----------------------- | ------------------------------------------- |
| Tuck robot (sit down)   | `roslaunch movo_demos tuck_robot.launch`    |
| Manual bringup + teleop | `bash ~/MOVO-SCRIPTS/movo_teleop.sh`        |
| Stop teleop             | `bash ~/MOVO-SCRIPTS/movo_teleop.sh stop`   |
| Robot demo              | `roslaunch movo_demos robot_demo.launch`    |
| Mapping                 | `roslaunch movo_demos robot_mapping.launch` |
