## Software & Setup

### System architecture

- **Ubuntu 22.04 Server** + **ROS 2 Humble**
- Clearpath stack installed with `clearpath_computer_installer.sh`
- `clearpath-platform` systemd service launches the base, twist_mux, joy teleop
- Robot config: `/etc/clearpath/robot.yaml` (sensor arch **not yet added** — sensors are launched by `husky_test.py`)
- NVIDIA driver 580 (`ubuntu-drivers autoinstall`)

### Access

<Callout type="info">
  Default login: `administrator` / `clearpath`. Hostname `cpr-a200-0392`.
  Connect your laptop to the **same network** as the Husky (not a phone
  hotspot). Last known IP `192.168.2.10`; check with `hostname -I` on the robot
  if it changes. Direct ethernet: set your laptop to `192.168.131.100/24`, no
  router, then use `192.168.131.1`.
</Callout>

```bash
ssh administrator@cpr-a200-0392.local      # or administrator@<ip>
source /etc/clearpath/setup.bash           # needed in every new shell before ros2 commands
```

### Boot & power

1. Release the E-stop.
2. Turn on the Husky main power switch.
3. The onboard PC boots automatically (BIOS set to power on when power returns). Wait ~60 s.
4. COMM light turns **green** once `clearpath-platform` is talking to the MCU.
5. Verify: `ping cpr-a200-0392.local`, then SSH in.

<Callout type="warning">
  **Always shut down the PC before cutting power:** `sudo poweroff`, wait for the
  PC to go dark, then turn off the main switch. The main switch cuts power
  without an OS shutdown — the previous SSD died with I/O errors.
</Callout>

### Teleop

1. Plug the DualSense in with a USB-C cable (or press PS if it is paired over Bluetooth).
2. Check: `ls -l /dev/input/ps4` should point to `js0`.
3. Hold **L1** (deadman) and use the **left stick**. Hold **R1** for turbo.
4. If nothing moves: `sudo systemctl restart clearpath-platform`, wait 20 s.

Check joystick input:

```bash
ros2 topic echo /a200_0392/joy_teleop/joy
```

### Data collection — `husky_test.py`

One script for everything: sensor capture, battery logging, per-component power profile and plots. It lives at `~/husky_test.py` on the robot.

```bash
./husky_test.py                                                   # interactive menu
./husky_test.py run --sensors --battery -d 0 --analyze -l teleop  # record while you teleop, Ctrl+C to stop
./husky_test.py run --battery drive -d 14400 --analyze -l rundown # battery rundown test (robot moves!)
./husky_test.py run --power                                       # per-component power profile (robot still)
./husky_test.py list
```

Sessions are saved to `~/husky_data/session_<date>_<label>/`:

| Path                            | Contents                                           |
| ------------------------------- | -------------------------------------------------- |
| `summary.txt`                   | All stats: battery, per-component power, sensor Hz |
| `sensors/video/dashboard.mp4`   | Kinect RGB, depth, lidar top-down, lidar 3D        |
| `sensors/lidar/lidar_viewer.html` | Interactive 3D lidar player                      |
| `bag/`                          | Raw mcap — open in Foxglove                        |
| `battery/telemetry.csv`         | 2 Hz electrical log                                |
| `plots/`                        | Battery and power charts                           |

## Troubleshooting

| Issue                                   | Possible Cause                                   | Solution                                                                 |
| --------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------ |
| Can't SSH / "Host is down"              | Laptop on a different network (e.g. phone hotspot) | Join the Husky's network; `ipconfig getifaddr en0` should match its subnet |
| COMM light red                          | PC not booted or `clearpath-platform` not running | Wait 60 s; `sudo systemctl restart clearpath-platform`                  |
| PC doesn't turn on with main switch     | BIOS not set to power on after AC loss           | BIOS → "Restore on AC Power Loss" = Power On                             |
| BIOS settings / boot order reset        | Dead CMOS coin cell                              | Replace CR2032 on motherboard                                            |
| Joystick does nothing                   | `/dev/input/ps4` missing                         | Check udev rule below, replug, restart platform                          |
| `ros2 topic` shows nothing              | Clearpath env not sourced                        | `source /etc/clearpath/setup.bash`                                       |
| Kinect ~3 Hz                            | CPU depth processing                             | GPU depth build (Open items)                                             |
| Battery columns blank in CSV            | `clearpath-platform` not running                 | Start the service before `husky_test.py`                                 |

<Callout type="info">
  DualSense udev rule (`/etc/udev/rules.d/99-dualsense.rules`) — the joy node
  hardcodes `/dev/input/ps4`:
  `KERNEL=="js*", SUBSYSTEM=="input", ATTRS{name}=="*DualSense Wireless Controller", SYMLINK+="input/ps4", MODE="0666"`
  Apply with `sudo udevadm control --reload-rules && sudo udevadm trigger`.
</Callout>


## Safety & Maintenance

<Callout type="danger">
  The Husky is heavy and fast. `drive`/`step` battery test modes move the
  robot several metres on their own — clear the area or put the wheels up,
  and keep the E-stop within reach. The joystick overrides scripted motion
  only while L1 is held.
</Callout>

### Best practices

- `sudo poweroff` before turning off the main switch
- Charge after every session (lead-acid degrades if left discharged)
- Run captures in `tmux`
- Pull data off the robot regularly — Kinect + lidar is ~2–3 GB/min
- Log all sessions in the change log
